# 代码审查报告 — 安全 / Bug / 优化

> 2026-08-15 全量审查（只读分析），覆盖 src/ 全部 24 个 .cs 文件。按「安全风险 → 正确性 Bug → 资源 → 性能 → 代码质量」排列，每条含文件:行号与修复建议。

## 总体结论

作为本地单用户工具，安全基线合格：反序列化无类型注入、MCI 无命令注入、宏名路径穿越已防护、Interception 过滤器 try/finally 复位完整（手册坑 16）、回放补发抬起基本完整（坑 17）。**没有远程可利用面、没有严重漏洞**。

最值得修的三类问题：
1. **安全**：不可信 config.json 经「软件控制」列表达成任意程序执行（唯一代码执行入口）
2. **正确性**：引擎 Stop→Start 竞态双线程并发注入（可能卡键）；「运行到时刻」跨天判断错误（过夜挂机失效）
3. **健壮性**：钩子回调内做磁盘 I/O（音效 MCI / 日志写文件），有被系统摘钩的风险（手册坑 1 部分未修复）

## 一、安全风险

### 高-1 恶意 config.json 可借「软件控制」功能任意执行程序
- 位置：`MainForm.cs:1966-1983`（LaunchPrograms，Process.Start 在 1974）、触发点 `MainForm.cs:1580`（回放开始）/ `MainForm.cs:200-206`（回放结束）；数据来源 `AppConfig.cs:50-52`
- 问题：`LaunchPrograms` 列表与 `LaunchOnStart/LaunchOnEnd` 开关直接来自 config.json，加载时无任何校验；`Process.Start(p)` 走默认 ShellExecute，可执行任意 exe/bat/cmd/lnk/URL。保存设置不会清空该列表，恶意条目一直存活。
- 触发场景：攻击者分发「宏包」诱导用户覆盖 config.json（含 `"LaunchPrograms":["C:\\...\\evil.bat"], "LaunchOnStart":true`）→ 用户打开任意宏点播放 → evil.bat 静默执行。
- 修复建议：加载配置时逐条校验 LaunchPrograms（必须绝对路径 + 扩展名白名单 exe/lnk，拒绝 bat/cmd/URL/文档）；或首次使用该列表时弹确认框。

### 中-1 钩子回调内执行 MCI 播放（磁盘 I/O）→ UI 阻塞 + 钩子被系统摘除
- 位置：`SoundFx.cs:121-157`（KeyboardProc 内直接 SfxPlayer.Play）、`SoundFx.cs:38-56`（File.Exists + open/setaudio/play 三次 mciSendString）
- 问题：LL 钩子回调在安装线程（UI 线程）消息循环中执行，回调内做磁盘 I/O 会冻结 UI，且可能超过 LowLevelHooksTimeout（约 300ms~1s）导致系统**静默摘除钩子**——热键/录制/音效全部失效且不报错。违反手册坑 1。
- 触发场景：绑定的 mp3 较大/首次播放/在慢盘或 UNC 路径上，快速连按该键。
- 修复建议：回调只入队（ConcurrentQueue），由后台线程执行 Play；KeyboardProc 整体加 try/catch（回调中托管异常穿越原生边界会终止进程）。

### 中-2 Interception 驱动注入不带 INJECTED 标记 → 回放触发自己的热键/音效
- 位置：`HotkeyManager.cs:424-445`（只过滤 LLKHF_INJECTED）、`SoundFx.cs:133`
- 问题：驱动层注入的输入没有注入标记，低级钩子当真实硬件输入处理。录制侧靠 `MacroRecorder.IsHotkeyKey` 回避了此问题，但**回放侧没有抑制**：宏里含 F6~F9/F12 时，驱动模式回放会触发自己的热键（按 F8 把回放停掉、按 F12 全停）；绑定音效的键会误播音效。
- 修复建议：回放期间置 HotkeyManager.Suppress（TryFire 加 _player.Playing 检查），SfxManager 同理。

### 中-3 ReleaseHeld 只跟踪最后一个按住键 → 恶意宏可残留多键按住
- 位置：`MacroPlayer.cs:25-27`（_heldKeyVk/_heldBtn/_heldCombo 单值）、`MacroPlayer.cs:98-121`、`MacroPlayer.cs:198-203`
- 问题：宏含多个 KeyDown 时后一个覆盖前一个的跟踪记录；停止时只补发最后一个键的抬起。SendInput 注入的键按下后无对应抬起，会保持系统级按下（进程退出也不自动释放，需物理按一次复位）。
- 触发场景：恶意宏连续两条 KeyDown（如 Win + Ctrl），回放中途按停止 → Win/Ctrl 系统级按住 → 用户后续按键全变组合键。
- 修复建议：_held* 改为 HashSet 集合跟踪并全部释放；已按下的键忽略重复 KeyDown。

### 低-1 config 音效绑定路径穿越 → 播放磁盘任意媒体文件
- 位置：`MainForm.cs:2083/2092/2244`（Path.Combine(AppConfig.SoundsDir, kv.Value) 无校验）
- 问题：kv.Value 可为 `..\..\Windows\Media\notify.wav` 或绝对/UNC 路径（Path.Combine 遇绝对路径直接返回）。UI 添加时截断文件名，但手工编辑 config 可绕过。
- 修复建议：加载时校验 `Path.GetFileName(kv.Value) == kv.Value`，非法项丢弃。

### 低-2 退出不等待引擎线程 → 注入键可能残留
- 位置：`MacroPlayer.cs:38-41`（Stop 只置标志）、`MainForm.cs:2739-2762`（Shutdown）、`KeyboardSpammer.cs:76-80`
- 问题：Shutdown 后进程立即结束，后台线程 ~10ms 察觉窗口内可能来不及 finally 补发抬起。
- 修复建议：Shutdown 对三个引擎线程 Join（超时 500ms）再退出。

### 低-3 恶意 Wheel 事件 Data=int.MinValue 导致驱动模式回放静默中断
- 位置：`InterceptionDriver.cs:156`（Math.Abs(delta) 对 int.MinValue 抛 OverflowException）
- 修复建议：`Math.Abs((long)delta)`。

### 低-4 日志注入（log.txt 行伪造）
- 位置：`MainForm.cs:1975`、`Log.cs:39-41` — 程序路径可含 \r\n 伪造日志行。建议 Log.Write 入口转义换行。

### 低-5 宏库页在 UI 线程反序列化全部宏文件 → 恶意宏包冻结界面
- 位置：`MainForm.cs:1725-1748`（RefreshMacroList 每次进页/切语言/DPI 重建全量反序列化）
- 修复建议：后台线程解析 + 按 LastWriteTime 缓存事件数；超大文件跳过。

### 低-6 多实例并发写 log.txt / config.json 竞争
- 修复建议：单实例 Mutex；日志轮转改 rename。

### 其他建议
1. InterceptionDriver 从不调用 interception_destroy_context（`InterceptionDriver.cs:100-113`），建议 Shutdown 时销毁。
2. explorer 参数引号不一致：`MainForm.cs:1919` 未加引号，`MainForm.cs:2252` 加了，统一。
3. 钩子安装失败静默（`HotkeyManager.cs:373-380`、`SoundFx.cs:106-111`），失败时 Log.Warn + 状态栏提示。
4. SaveMacro 非原子写（`MainForm.cs:1667`），建议 tmp+Replace。
5. config 加载失败提示偏弱，建议 Log.Warn 完整异常。

### 已确认安全（查证过）

- AutoStart 注册表值带引号完整路径，无注入面
- Interception 过滤器 try/finally 复位完整（坑 16 ✅）
- 崩溃兜底链路完整（ThreadException + UnhandledException + 引擎 finally 松键）

## 二、正确性 Bug

### B1【高】引擎 Stop→Start 竞态：旧线程未退净时重新启动 → 双线程并发注入
- 位置：`AutoClicker.cs:24-80`、`KeyboardSpammer.cs:27-83`、`MacroPlayer.cs:30-95`
- 问题：Stop() 只置 false 不等待线程退出，Start() 见 flag 为 false 就再开线程。旧线程在阻塞操作中（轨迹移动最长 ~1200ms）不检查标志，醒来看到 flag 又是 true 继续跑 → 双线程同时注入；_held* 是两代线程共享的无锁状态，旧线程 finally 的 ReleaseHeld 会把新线程按住的键补发抬起 → 卡键。
- 触发场景：回放带长轨迹的宏时按停止，1.3 秒内再按启动。
- 修复建议：代际计数（int _gen，Stop 自增，循环内比对）或 Stop 后 Join 再允许 Start；_held* 改为 Run() 局部变量。

### B2【中】「运行到时刻」跨天判断错误（过夜挂机失效）
- 位置：`MacroPlayer.cs:73-82`
- 问题：`DateTime.Now >= DateTime.Today.Add(until.TimeOfDay)` 只取"今天"；22:00 设"运行到 03:00"→ 条件立即为真，跑一轮就停。
- 修复建议：若目标时刻早于当前时刻则 AddDays(1) 再比较；TryParseExact 失败时 Log.Warn。

### B3【中】HotkeyCaptureForm 无注入过滤 + 点击对话框本身即捕获鼠标键
- 位置：`HotkeyCaptureForm.cs:75-146`（无 LLKHF_INJECTED/LLMHF_INJECTED 检查）、`148-161`
- 问题：唯一不过滤注入标记的钩子；对话框客户区内点击即把"鼠标左键"收录为组合键并直接完成捕获。
- 修复建议：down 分支加注入标记过滤；点击落在窗体 Bounds 内则忽略。

### B4【中】SfxManager 钩子回调内执行 MCI open/play（同 中-1）
- 位置：`SoundFx.cs:121-157` — 回调超时被摘钩后音效静默失效 + UI 卡顿。

### B5【中】副屏在主屏左侧时录制/回放坐标损坏
- 位置：`MacroRecorder.cs:142-155`（Sanitize 负坐标钳 0）、`InputSimulator.cs:279-293`（负坐标 (uint) 强转）
- 问题：副屏在左时 GetCursorPos 返回负坐标；保存再加载时 Sanitize 钳为 0；SendInputMove 对负 double 强转 uint 结果错乱 → 回放全部指向主屏左上角。
- 修复建议：Sanitize 允许负坐标（≥ -32768）；SendInputMove 先 Math.Max(0, ...) 再除。

### B6【低】鼠标/键盘共用一个 _holdSw → 长按被误合并成单击
- 位置：`MacroRecorder.cs:65`（_holdSw 共享）、`226-253`、`276-303`
- 触发场景：长按 W 走路时点了下鼠标，随后 250ms 内松开 W → 长按被改写成 KeyTap。
- 修复建议：鼠标/键盘各用一个 Stopwatch，或按 down 时间戳判断。

### B7【低】跨线程共享字段未按声明策略加 volatile
- 位置：`Humanizer.cs:20-21`（TimingJitterPct/PositionJitterPx 注释说 volatile 但未加）、`InputSimulator.cs:30-36`（Method/TargetWindowTitle/KeyboardScanCode）
- 影响：连点运行中改设置可能"改了没生效"。修复建议：补 volatile。

### B8【低】HotkeyManager.Describe 硬编码中文 → 英文界面显示"(未设置)"
- 位置：`HotkeyManager.cs:344` — Lang.cs:260 已有 "(unset)" 键却无调用点。改为 Lang.T("(unset)")。

### B9【低】Ui() 在窗口句柄未创建时可能让引擎线程直接碰控件
- 位置：`MainForm.cs:2584-2589` — InvokeRequired 在句柄未创建时返回 false。静默启动下引擎 300ms 内结束会跨线程操作 UI。建议先 IsHandleCreated 判断（否则 CreateControl 后 BeginInvoke）。

### B10【低】其他小问题
- `MainForm.cs:2450`：音量标签用配置原始值，越界时与滑块显示不一致 → 用滑块 Value
- 三个引擎 `catch (Exception) {}` 空吞（AutoClicker.cs:70-73 等）→ 补 Log.Warn
- `HotkeyManager.cs:373-380`：键盘钩子成功、鼠标钩子失败后不再重装 → 失败回滚并允许重试
- `MacroPlayer.cs:71-72`：RunMinutes/UntilTime 只在轮间检查，超长单轮越过时限（可接受，建议文案注明）
